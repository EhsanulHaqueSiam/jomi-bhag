    - mergeParcel: Given split items with same parentId, returns them merged back into original item

    - calculateIndividualCompensations: Given individuals [{id:'son_0', cashAdjustment:30000}, {id:'daughter_0', cashAdjustment:-30000}], returns [{fromId:'son_0', toId:'daughter_0', amount:30000}]. Greedy matching of largest surplus with largest deficit, minimize transfer count

    - computeIndividualFingerprint: Includes property IDs+values, movable asset IDs+values, AND heir type counts
  </behavior>
  <action>
    Create `src/core/distribution/individual-types.ts` with:
    - `IndividualColumn` interface: id (string, e.g. "son_0"), heirType (HeirType), index (number), displayName (string, e.g. "Son 1"), customName (string | null), targetValue (number), sharePerHeir (string -- serialized fraction), assignedItems (string[]), assignedValue (number), cashAdjustment (number)
    - `SplitParcel` interface: id (string -- crypto.randomUUID()), parentId (string -- original DistributionItem id), label (string -- "Beki (5 shotok)"), areaSqft (number), value (number)
    - `IndividualCompensation` interface: fromId (string), fromName (string), toId (string), toName (string), amount (number)
    - `IndividualDistributionResult` interface: individuals (IndividualColumn[]), items (DistributionItem[] -- includes split sub-parcels as regular items), compensations (IndividualCompensation[]), totalEstateValue (number)
    - Export a `COMPENSATION_THRESHOLD = 100` constant (minimum BDT for a compensation entry)

    Create `src/core/distribution/individual-algorithm.ts` with pure functions:
    1. `expandGroupsToIndividuals(groups, shares)` -- expand each DistributionGroup into count IndividualColumn objects. Use composite ID `${heirType}_${index}`. Use HEIR_TYPE_LABELS for displayName (e.g., "Son 1", "Consanguine Brother 2"). Per-subtype numbering: sons numbered separately from brothers.
    2. `subdivideGroupItems(items, individuals, groupHeirType)` -- for a single group's items, distribute them among that group's individuals. Sort items by value descending, round-robin assignment. For movable items that are "indivisible" (single high-value item), assign to first individual. Returns updated individuals with assignedItems and assignedValue.
    3. `splitParcel(originalItem, splits, totalAreaSqft)` -- create new DistributionItem entries from split definitions. Each gets proportional value. Last sub-parcel gets remainder value (originalValue - sum of others) to prevent rounding drift. ID via crypto.randomUUID(). Label: "${originalLabel} (${formatArea(areaSqft)})". Return array of new items.
    4. `mergeParcel(splitItems, originalItem)` -- given split items with same parentId, remove them and restore the original item. Returns { removedIds: string[], restoredItem: DistributionItem }.
    5. `individualQurahShuffle(items, individuals)` -- same algorithm as smartShuffle but operating on IndividualColumn[] instead of DistributionGroup[]. Sort items by value descending, for each item find individuals with most remaining gap, pick randomly from top candidates (within 80% of best gap). Return new individuals array with recalculated assignedValue and cashAdjustment.
    6. `calculateIndividualCompensations(individuals)` -- greedy min-transfer algorithm. Build surplus/deficit lists from cashAdjustment. Match largest surplus with largest deficit, transfer min of both. Filter out transfers below COMPENSATION_THRESHOLD. Return IndividualCompensation[].
    7. `moveIndividualItem(individuals, items, itemId, fromId, toId)` -- move item between individuals (by individual id, not heirType). Immutable return. Recalculate assignedValue and cashAdjustment for all.
    8. `computeIndividualFingerprint(wizardState)` -- JSON.stringify of property IDs+values, movable asset IDs+values, AND heir type counts (sonCount, daughterCount, wifeCount, etc.).
    9. `initializeIndividualDistribution(distributionResult, shares)` -- orchestrator: calls expandGroupsToIndividuals, then subdivideGroupItems for each group, then calculateIndividualCompensations. Returns IndividualDistributionResult.

    - 3 sons + 2 daughters expansion = 5 individuals with correct targets
    - Single wife gets her own column
    - Parcel split values sum exactly to original (no floating point drift)
    - Merge restores original item
    - Qurah shuffle assigns all items, no item lost
    - Compensation minimizes transfers (3 surplus + 2 deficit = max 4 transfers)
    - Fingerprint changes when heir count changes
