  <action>
    **src/core/faraid/types.ts** -- The complete type system:

    1. `HeirType` enum/union: `husband`, `wife`, `son`, `daughter`, `son_of_son`, `daughter_of_son`, `father`, `paternal_grandfather`, `mother`, `paternal_grandmother`, `maternal_grandmother`, `brother_full`, `brother_consanguine`, `brother_uterine`, `sister_full`, `sister_consanguine`, `sister_uterine`. This covers all 12 Dhawul Furud plus grandchildren for MFLO.

    2. `HeirInput`: `{ type: HeirType; count: number }` -- how the user specifies heirs.

    3. `FaraidInput`: `{ deceasedGender: 'male' | 'female'; heirs: HeirInput[]; mfloEnabled?: boolean }` -- engine input.

    4. `ShareResult`: `{ heirType: HeirType; count: number; sharePerHeir: Fraction; totalShare: Fraction; shareType: 'fard' | 'asaba' | 'radd_adjusted' | 'blocked'; quranRef?: string; hadithRef?: string; explanation: string; notes?: string[] }` -- per-heir output.

    5. `AdjustmentType`: `'none' | 'awl' | 'radd'`

    6. `FaraidOutput`: `{ shares: ShareResult[]; adjustment: AdjustmentType; totalBeforeAdjustment: Fraction; blockedHeirs: { heirType: HeirType; blockedBy: HeirType; rule: string }[]; specialCases: string[]; mfloApplied: boolean; steps: CalculationStep[]; references: IslamicReference[] }`

    7. `CalculationStep`: `{ step: number; description: string; detail: string }` -- for step-by-step explanation.

    8. `IslamicReference`: `{ type: 'quran' | 'hadith'; reference: string; arabicText: string; englishText: string; appliesTo: HeirType[] }`

    9. `ShareCondition`: `{ share: Fraction; when: string; predicate: (ctx: HeirContext) => boolean }`

    10. `HeirContext`: derived from FaraidInput -- boolean flags and counts for all heir types, for predicate evaluation.

    11. `FaraidRule`: `{ heirType: HeirType; shareType: 'fard' | 'asaba' | 'fard_and_asaba'; conditions: ShareCondition[]; quranRef: string; hadithRef?: string }`

    12. `BlockingRule`: `{ blocker: HeirType | HeirType[]; blocked: HeirType | HeirType[]; type: 'total' | 'partial'; condition?: string; note?: string }`

    13. `AsabaType`: `'bi_nafsihi' | 'bi_ghayrihi' | 'ma_a_ghayrihi'`

    **src/core/utils/fraction.ts** -- Fraction wrapper:
    - Import Fraction from 'fraction.js'
    - Export 6 Quranic named constants: HALF, QUARTER, EIGHTH, TWO_THIRDS, ONE_THIRD, ONE_SIXTH
    - Export ZERO and ONE
    - Export helpers: sumFractions, exceedsOne, lessThanOne, formatShare

    **src/data/quran-references.ts** -- Static Quranic data:
    - Map keyed by surah:ayah (e.g., "4:11", "4:12", "4:176")
    - Each entry: `{ surah: number, ayah: number, arabicText: string, englishTranslation: string, context: string }`
    - Must include Surah An-Nisa 4:11 (children shares), 4:12 (spouse/uterine shares), 4:176 (Kalalah/siblings)
    - Arabic text must be the actual Quranic Arabic (not transliteration)

    **src/data/hadith-references.ts** -- Static Hadith data:
    - Array of `{ id: string, source: string, narrator: string, arabicText?: string, englishText: string, appliesTo: string[] }`
    - Include: father as Asaba (Sahih Bukhari), grandfather blocking siblings (Hanafi consensus), grandmother's 1/6 (Muwatta), Umariyyatayn (Omar's ruling)

    **src/data/faraid-rules.ts** -- Declarative rule table:
    - Complete set of FaraidRule entries for all 12 Dhawul Furud heir types from RESEARCH.md table
    - Each rule has conditions as ShareCondition[] with predicate functions
    - Each rule has quranRef linking to quran-references data
    - Use the named Fraction constants from fraction.ts (HALF, ONE_SIXTH, etc.) -- never raw numbers
    - Include all conditional share variations from the RESEARCH.md "12 Dhawul Furud" table

    **src/core/faraid/references.ts** -- Reference lookup:
    - `getShareReference(heirType, condition)` -- returns the Quranic/Hadith reference for a specific share allocation
    - `getBlockingReference(blocker, blocked)` -- returns the reference for a blocking rule
    - `getAdjustmentReference(type: 'awl' | 'radd')` -- returns references for adjustment mechanisms
    - `getAllReferences(output: FaraidOutput)` -- collects all unique references used in a calculation result

    **src/core/faraid/validation.ts** -- Input validation:
    - `validateHeirInput(input: FaraidInput)` returns `{ valid: boolean; errors: string[] }`
    - Checks: all counts >= 0, wife count <= 4, husband count <= 1, deceased gender consistent with spouse type (male deceased has wife not husband, etc.), at least one heir present
    - Does NOT check Islamic validity (that is the engine's job) -- only structural validity

    Write tests FIRST (RED), then implement (GREEN). Tests go in `src/core/faraid/__tests__/validation.test.ts` for validation, and a new `src/core/faraid/__tests__/types-and-utils.test.ts` for fraction utils and rule table completeness checks.
