    **src/core/faraid/residuary.ts:**

    1. `classifyAsaba(heirType: HeirType, ctx: HeirContext): { type: AsabaType; priority: number } | null`:
       - Returns null if heir is not Asaba in this context
       - Asaba bi-nafsihi: son (priority 1), son's son (2), father (3, only when no children), grandfather (4), full brother (5), consanguine brother (6), son of full brother (7), son of consanguine brother (8), full paternal uncle (9), consanguine paternal uncle (10)
       - Asaba bi-ghayrihi: daughter with son, son's daughter with son's son, full sister with full brother, consanguine sister with consanguine brother
       - Asaba ma'a ghayrihi: full sister(s) with daughter(s), consanguine sister(s) with daughter(s) (when no full siblings)

    2. `assignResiduary(activeHeirs: HeirInput[], fixedShares: ShareAssignment[], ctx: HeirContext): ShareAssignment[]`:
       - Calculate remainder = ONE - sumFractions(all fixed shares)
       - If remainder <= ZERO: return fixedShares unchanged (Awl will handle)
       - Identify Asaba heirs among activeHeirs using classifyAsaba
       - If no Asaba: return fixedShares unchanged (Radd will handle)
       - Distribute remainder to highest-priority Asaba tier:
         * bi-nafsihi: highest priority Asaba gets entire remainder. If multiple at same priority (e.g., 3 sons), divide equally
         * bi-ghayrihi: male gets 2x female share of remainder (Quran 4:11 "for the male, twice the share of the female")
         * ma'a ghayrihi: sister(s) take entire remainder
       - Father special case: when daughters exist but no sons, father gets 1/6 fard + remainder. Model as fard_and_asaba shareType
       - Add Asaba shares to output with shareType='asaba' and appropriate Quranic references

    **src/core/faraid/adjustments.ts:**

    1. `applyAwl(shares: ShareAssignment[]): { adjusted: ShareAssignment[]; explanation: CalculationStep }`:
       - Sum all fixed shares. If sum <= ONE, return unchanged
       - Find LCM of all share denominators (will be 6, 12, or 24)
       - Convert all shares to common denominator
       - Sum numerators -> this is the Awl denominator
       - Each heir's adjusted share = their numerator / Awl denominator
       - Verify: sum of adjusted = ONE exactly (use fraction.js equals)
       - Build explanation step showing: original shares, why they exceed 100%, the proportional reduction math
       - Per locked decision: "show full explanation -- original shares, why they exceed 100%, proportional reduction with math"

    2. `applyRadd(shares: ShareAssignment[]): { adjusted: ShareAssignment[]; explanation: CalculationStep }`:
       - Sum all fixed shares. If sum >= ONE, return unchanged
       - Calculate remainder = ONE - sum
       - Identify Radd-eligible heirs: all fixed-share heirs EXCEPT spouse types (husband, wife)
       - If no Radd-eligible heirs: return unchanged with note "Remainder directed to Bait-ul-Maal"
       - Distribute remainder proportionally based on original share ratios among eligible heirs
       - Each eligible heir's Radd portion = remainder * (their_share / sum_of_eligible_shares)
       - Verify: sum of all shares (including unchanged spouse) = ONE exactly
       - Build explanation step: "Hanafi ruling: spouses excluded from Radd. Remainder distributed to blood-relative fixed-share heirs."
       - Per locked decision: "explain Hanafi ruling that spouses are excluded from surplus redistribution, note why"

    3. `applyAdjustment(shares: ShareAssignment[]): { adjusted: ShareAssignment[]; adjustmentType: AdjustmentType; explanation?: CalculationStep }`:
       - If exceedsOne(sum): return applyAwl(shares) with adjustmentType='awl'
       - If lessThanOne(sum) AND no Asaba shares present: return applyRadd(shares) with adjustmentType='radd'
       - Otherwise: adjustmentType='none', return unchanged
